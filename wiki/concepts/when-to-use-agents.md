# 什麼時候該用 Agent？

## 先從最簡單的開始
- 先找最簡單的解法，必要時才加複雜度，甚至可能根本不需要 agentic system。〔raw:01〕
- 很多應用只要把一次 LLM 呼叫（加上檢索和範例）優化好就夠了。〔raw:01〕
- Agentic system 是用延遲和成本換取更好的任務表現。〔raw:01〕

## OpenAI 的三個判斷條件
1. **複雜決策**：需要細緻判斷、處理例外，例如退款審核。〔raw:04〕
2. **難以維護的規則**：規則多又複雜，例如供應商資安審查。〔raw:04〕
3. **大量非結構化資料**：要理解文件、跟使用者對話，例如房屋保險理賠。〔raw:04〕
- 都不符合的話，用確定性的（deterministic）解法可能就夠了。〔raw:04〕
- 比喻：規則引擎像一張檢查清單，agent 像經驗豐富的調查員。〔raw:04〕

## 適合 agent 的任務特徵
- 同時需要對話和行動、成功標準清楚、能形成回饋循環、有人類監督，例如客服、寫程式。〔raw:01〕
- 程式碼可以用自動化測試驗證，agent 能根據測試結果反覆修改。〔raw:01〕
